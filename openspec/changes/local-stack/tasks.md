- [x] 17.15 **Record that no application has network redundancy, and that the per-app network pattern already accommodates it.** Each application's network is a single bridge with no second path and no failover, and there is no second attachment of the core to anything. Recorded as estate-level, again without an owner named here. The useful part is not the gap but that the remedy is nearly free *because* of the pattern adopted in this change: an application owns its network, so a second network is added on the application side and the core is connected to both — the core changes nothing. Under the arrangement this change rejected, where the application joined a network the core declared, redundancy would have required a coordinated change across the core and every consumer, which is the coupling this change removes. The residual risk to state plainly: because a container's attachment dies with the container, a recreate silently drops it, so any second path needs a check that both attachments are present, not an assumption that they are. Not implemented here — it needs its own decision about what fails over and to where.
