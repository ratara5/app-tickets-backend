# Troubleshooting — gate failures only

Diagnose by layer: clients, TLS edge, app, data services. A symptom belongs to exactly
one layer, and fixing the wrong layer wastes the outage.

## Media — the "login works, photos do not" class

| Symptom | Likely cause | First command |
|---|---|---|
| `403 SignatureDoesNotMatch` | URL signed for a different host than the client used | compare the configured endpoint with the host in the failing URL |
| `403 AccessDenied` on a large file only | multipart actions missing from the policy | review the bucket- and object-level actions |
| Loads in a browser, fails in the app | the browser is not enforcing CORS, or the reverse | test with `curl` from outside the server |
| `NoSuchKey` right after a successful upload | bytes were never moved out of staging | check the staging directory and the move step |
| Loads locally, not from a phone | endpoint is an internal name, or the proxy strips `Host` | fetch the presigned URL from a different network |
| Upload works via the API, fails direct from a browser | bucket CORS not set | see the CORS table in `media-and-minio.md` |
| Everything media-related broke right after a release | endpoint or bucket changed in config | diff the config against the previous release |

## Data plane

| Symptom | Likely cause | First command |
|---|---|---|
| `connection refused` to the database from the app | not on the shared network, or wrong internal port | `docker network inspect <net>` |
| `could not translate host name` | app is on the host, not the network; container names only resolve inside it | move the process into a container, or publish a port for development |
| `permission denied for schema` | role is not the owner | `\dn+` and check ownership |
| `too many connections` | pool size multiplied by workers and replicas | count pools, then right-size |
| `value too long for type character varying(32)` on a history table | migration identifiers exceed the column | widen the column before stamping |

## Application stack

| Symptom | Likely cause | First command |
|---|---|---|
| Container healthy, every request 500 | a required setting was defaulted, not configured | read the startup log, compare against the config file |
| Settings error naming an unexpected field | the env file was sourced by a shell and JSON lost its quotes | read the file with the app's own parser; see `env-matrix.md` |
| Uploads fail only above a few MB | a body-size cap at the proxy or in the app | compare both limits with the expected size |
| Works locally, fails on the server | an internal hostname leaked into config | grep the config for container names and `localhost` |

## TLS edge

| Symptom | Likely cause | First command |
|---|---|---|
| Certificate not issued | port 80 not reachable, or the contact address is invalid | `curl -I http://<domain>/.well-known/acme-challenge/` |
| Works for one domain, not the other | a second proxy (CDN, tunnel) in front without certificates | `dig +short <domain>` |
| Redirect loop behind a proxy | the app trusts the wrong proxy headers | inspect the forwarded headers the proxy sets |

## Tenancy

| Symptom | Likely cause | Action |
|---|---|---|
| A container you do not own is missing | a step removed shared state | **stop**, restore from the pre-flight backup, report |
| A named volume or database you do not own is missing | a destructive command was run on shared state | **stop**, restore, identify the command in the shell history |
| The diff shows only 64-hex lines | anonymous volume ids, recreated by unrelated containers | ignore; they are not a tenancy signal |
| Another tenant's app returns 5xx | the shared container was restarted or is overloaded | check `docker ps` for restarts, read its logs, report before touching anything |

## Database creation

Schema scripts fail differently depending on the server image, so check the image
before concluding anything:

```bash
docker inspect <pg-container> --format '{{.Config.Image}}'
docker exec <pg-container> psql -U <admin-user> -d postgres -tAc \
  "SELECT name, default_version FROM pg_available_extensions WHERE name = '<extension>'"
```

A stock `postgres:16` image ships only `plpgsql`, `uuid-ossp` and `pgcrypto`. A
custom-built image may carry more. An `ERROR: extension ... is not available` therefore
means *this server lacks it*, not that the script is wrong.

| Symptom | Cause | Fix |
|---|---|---|
| `extension "..." is not available` | the target image does not ship that extension | use the image the existing databases were built on, or install the extension |
| `foreign key constraint "..." cannot be implemented` | incompatible column types across the key (`VARCHAR` to `SERIAL`) | correct the column types; PostgreSQL cannot create it and later statements still run |
| "the load finished" but tables are missing | `psql` continues after an error | always `-v ON_ERROR_STOP=1`, and grep the output for `ERROR` |
| `relation "..." does not exist` while migrating | migrations are deltas that assume a base schema | create the base schema from the ORM metadata, then stamp the history |
| `Multiple head revisions are present` | the history graph branched | `upgrade heads` (plural) as an interim measure; merge the branch |
| `value too long for type character varying(32)` | revision ids exceed the history table's default column | create the history table wider before stamping, e.g. `VARCHAR(64)` |
| A database that "works" has a history table no script creates | someone patched it by hand | record the real state, then reconcile the scripts with it |
| The app works but re-running the schema fails | the app generates those values in the client, so the extension is only needed by the scripts | still report it: the next schema change will fail on that server |
