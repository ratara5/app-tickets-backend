# Legacy Seed Removal

**Input**: a consumer that holds a legacy seed, and the harness's recorded
fingerprints (`legacy-seed.yaml`). If the fingerprints do not name this consumer's
commit, stop — the classification would call every seed file UNKNOWN and delete
nothing, which looks like success and is not.

**Core principle**: classify every file, and delete only what you can prove is a
copy of something the harness now owns. A migration's dangerous failure is not
"deleted too little"; it is "deleted a file that had diverged from the seed, and
the divergence was the consumer's only copy."

## Preconditions

Run all of these before touching anything.

- [ ] `pre-agentic-layer` tag exists, at the commit the migration starts from. If
      it is missing, tag HEAD — the last commit before migration is the pristine
      state — and create a bundle backup (`git bundle create …`). If it is missing
      **and** the working tree is dirty, snapshot first (`cp -a`) and stop.
- [ ] `.agentic.lock` exists means the projection is already installed: skip
      "install projection". If the consumer already ran on the harness (an
      upgrade, not a first migration), skip install *and* removal — bump the pin,
      run `agentic sync`, verify. There is no seed to remove.
- [ ] The harness records this consumer's commit in `legacy-seed.yaml`. If it does
      not, stop and ask for the seed source; do not guess hashes.

## The classification is a dry run, and it is the approval artefact

```sh
agentic --consumer . legacy
```

This writes nothing. It prints one line per candidate path and a summary. Every
path is exactly one status:

| Status | Meaning | Action |
|---|---|---|
| `IDENTICAL` | content matches the recorded seed | deletable, after approval |
| `MODIFIED` | a seed path whose content changed | salvage first, then delete |
| `UNKNOWN` | not a seed path at all | **never delete** |
| `SYMLINK` | a link; handled separately below | replace in the projection commit |
| `PROJECTED` | the harness writes this exact path | **never delete** — it is output |
| `MISSING` | a seed path that is not present | nothing to do |
| `CONSUMER-OWNED` | under `docs/` or `openspec/` | never touched |

`UNKNOWN` is the whole safety property. A tool-owned file —
`settings.local.json`, `settings.json`, `.mcp.json`, `opencode.json`,
`package.json`, `package-lock.json`, `node_modules/`, tokens, caches — is not in
the seed, so it is UNKNOWN, so it is left alone. So is anything the consumer
added. The classifier cannot delete by omission.

`PROJECTED` is the second safety property, and it is why re-running the
classification *after* the projection is safe. A seed entry the harness also
writes is `PROJECTED`, not `IDENTICAL`, even when the bytes still match: the
projection owns that path, and deleting it would delete the projection. This is
also why a seed symlink path that now holds a projected directory reports
`PROJECTED` rather than crashing.

**The expected first run is 45 `IDENTICAL`, 17 `PROJECTED`, 27 `SYMLINK` and a
small number of `UNKNOWN` tool files.** A materially different shape means the
seed source is wrong, and the answer is to stop, not to proceed.

## Agent directories: classify per file, never per directory

The candidate set is the contents of `.claude/`, `.opencode/`, `.cursor/`,
`.codex/`, `.gemini/`, plus the entrypoints (`CLAUDE.md`, `AGENTS.md`,
`GEMINI.md`, `codex.md`) and `ai-specs/`.

- **Never delete a directory wholesale.** The projection writes *into* these
  directories. Removing `.opencode/` to "clean it up" deletes the projection's own
  home and every UNKNOWN file inside it.
- Delete only files whose status is `IDENTICAL`.
- A directory left empty after removal is kept if the projection will use it, and
  removed otherwise — as an explicit step, after the files, never as a side effect.
- `docs/` and `openspec/` are `CONSUMER-OWNED`. Sync never writes them and this
  procedure never touches them.

## Symlinks

A legacy consumer often keeps its entrypoints and skills as symlinks into
`ai-specs/`. Two facts decide what happens:

- **Sync refuses to write through a symlink** (it would land on the target, not
  the path), so a symlinked path the projection occupies must be replaced in the
  **same commit as the projection**: remove the link, then project the real files.
- **Never delete the symlink's target as part of this.** The target is often the
  consumer's own canonical document; the link is what is superseded, not the
  document.

Record every symlink with its target and what resolves through it, in a separate
section of `MIGRATION_PLAN.md`. Before removing one, confirm nothing else
references its target. `ai-specs/specboot-instructions.md -> ../README.md` is the
common case: the link goes, the README stays.

## Collisions

The projection occupying the same path as a seed file is expected, not an error:

| Projected path holds | Rule |
|---|---|
| an `IDENTICAL` seed file | allowed; the projection overwrites it after approval (git history keeps the original) |
| a `MODIFIED` file | stop; salvage first |
| an `UNKNOWN` file | stop; report and ask |

## Steps

1. **Inventory** — run `agentic --consumer . legacy`.
2. **Write `MIGRATION_PLAN.md`** — per-file classification (`IDENTICAL` /
   `MODIFIED` / `UNKNOWN` / `CONSUMER-OWNED`), with symlinks in their own section
   naming target and referrers.
3. **STOP for approval.** Do not proceed on your own judgement of the plan.
4. **Install the projection** — write `.agentic.yaml`, `agentic sync` (skip if
   `.agentic.lock` exists). This replaces symlinked paths with real files in the
   same commit, per the symlink rule.
5. **Salvage `MODIFIED` files** — the consumer's divergences go into the
   consumer's `docs/`, and anything generic enough to belong in the harness goes
   into `HARNESS_PROPOSALS.md` as a proposal. Never patch the harness from the
   consumer.
6. **STOP for diff approval** of the salvage.
7. **Remove only `IDENTICAL` files**, in a separate commit.
8. **Verify**, then **deliver**.

## Verify

- [ ] `agentic sync --check` exits 0.
- [ ] The consumer's tests pass.
- [ ] `git diff pre-agentic-layer -- docs openspec` is empty, except approved
      salvage additions in `docs/`.
- [ ] No dangling references in the `Makefile`, scripts, CI or README to removed
      paths.
- [ ] No symlinks remain outside `venv/` and `node_modules/`.
- [ ] `UNKNOWN` files in the agent directories are byte-identical to the tag.
- [ ] A fresh agent session finds the commands and skills through the generated
      entrypoint, not through `ai-specs/`.

## Deliver

Four commits, each ending with an `Agentic-Layer: x.y.z` trailer:

1. projection + lock (including symlink replacement)
2. salvage
3. seed removal
4. reference fixes

Final report: what was deleted, what was salvaged, what `UNKNOWN` was left, any
harness gaps found, and the rollback command (`git revert` the removal commit, or
restore from the `pre-agentic-layer` tag). Open a PR; do not merge.

## Stop and ask if

- A classification is unclear.
- Deletion would change build, test or CI behaviour.
- Any step would write to or delete a `CONSUMER-OWNED` path.
- The projection lacks something the seed provided. Report it as a **harness
  gap**; never patch it in the consumer.
