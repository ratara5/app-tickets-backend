# Environment Matrix — deploying to a VPS with shared data services

The project's own `.env.example` is the authoritative list of keys. This file records
the rules that make such a file safe to parse, and the per-component settings that are
wrong most often. Names below are generic; substitute the project's.

## Format rules (not cosmetic)

| Rule | Why |
|---|---|
| No spaces around `=` | `set -a; . ./.env` and systemd `EnvironmentFile` both mis-parse them |
| No inline comments | the comment becomes part of the value (`TTL=1  # hours` is not an int) |
| Quote only when needed | quotes are literal in some parsers |
| No bare JSON with spaces around `:` or `,` | see the sourcing trap below |

## The `.env` sourcing trap

```bash
set -a; . ./.env     # WRONG when any value contains JSON
```

Bash performs quote removal on the *whole* line, so a value such as
`ALLOWED_TYPES=["a","b"]` becomes `ALLOWED_TYPES=[a,b]`. Whatever parses that file
next — pydantic, `json.loads`, a validator — fails with a field-level error that names
a setting nobody was looking at.

**Rule**: an application reads its own env file with its own parser. A shell script
reads only the individual, shell-safe values it needs, one at a time:

```bash
read_env_value() { sed -n "s/^$1=//p" .env | tr -d '\r' | tail -1; }
DB_NAME="$(read_env_value DB_NAME)"
```

Never `source`, never `export $(grep '=' .env)`. A value containing spaces or `#` will
either abort the script or be mangled.

## Values by component

### Identity

| Var | Purpose | Failure if wrong |
|---|---|---|
| API host | public API origin | wrong `Host` header, redirects to the wrong origin |
| Media host | the origin the app signs object URLs for | changing it invalidates every URL already sent to a client |
| ACME contact | registration address | cannot obtain a certificate |

The media host must be the address **clients** use, with the scheme, port and TLS
setting the app prepends when signing. The container-to-container address is an
internal detail; if a signature is computed for the internal name, the client gets
`403 SignatureDoesNotMatch`.

### PostgreSQL

| Var | Notes |
|---|---|
| host | the shared container's name on the shared network, not `localhost` |
| port | the container's internal port; it publishes no host port |
| database / user | the dedicated database and role, never the instance's admin user |
| password | generated on the box; never in a compose file or a commit |
| pool size | leave the default unless the server is small; per-worker pools multiply |

An app running on the host (not in a container) cannot resolve a container name; use
`localhost` plus a published port for local development only, never on the VPS.

### Object storage

| Var | Notes |
|---|---|
| endpoint | as above, the client-facing host |
| secure | `true` when clients use TLS |
| access/secret key | a **service account** key, scoped to one bucket |
| bucket | one bucket per app; never another app's |
| staging directory | local disk for in-flight uploads, must be a real writable path, not the app's read-only layer |

If the endpoint uses a hostname that resolves to the proxy, the proxy must forward the
original `Host` header, or signature validation fails.

### Runtime, disk, auth

| Var | Notes |
|---|---|
| log level | `info` in production; `debug` leaks request bodies into logs |
| secret key | at least 32 bytes, generated; a short one is an outage waiting to happen |
| token lifetime | long enough for a shift, short enough to matter when a phone is lost |
| upload size cap | must match the proxy's cap, or large uploads fail at the edge |
| staging dir capacity | a full disk breaks uploads before it breaks anything else |

### Compose-only variables

Some values exist only to the compose file (image tags, published ports, ACME
settings). Keep them out of the application settings, and keep every application's
compose file on the same shared network.

## Secrets handling

- Generate on the box; never paste a real secret into a runbook, ticket or commit.
- `.env` is git-ignored; verify with `git check-ignore -v .env`.
- A secret committed once is compromised: rotate it, do not just delete the line.
- Prefer a service account's derived key over the parent user's own secret, so the
  parent's credential is only used to mint others.
- Mask in reports: `AKIA…****`, `****`.

## Validating before boot

```bash
grep -cE '^[[:space:]]*[^#[:space:]][^=]*=' .env   # count of real assignments
docker compose config >/dev/null                    # interpolation errors surface here
```

Then boot the application and confirm it reports the values you expect rather than
falling back to defaults. A silently defaulted setting is the most expensive kind of
mistake: the app is healthy and the clients are broken.
